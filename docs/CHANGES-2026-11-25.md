## 二、真机探测结论（64 项全表核实，75 秒）

- `FlagInfo` 的 **64 条档位/量程全部被设备接受**（逐条发 `AF 05 03 06 01 <flag>`，回帧 `data[5]` 全部对上）。
- **13 个未登记候选全部被拒**（`0x06 0x07 0x0B 0x13 0x1B 0x33 0x3B 0x43 0x46 0x47 0x73 0x9B 0xBF`）→ 协议的档位列就这 64 个。
- **AUTO+ 是真实功能**：`0x30 / 0x70 / 0xB0 / 0x39 / 0x79 / 0xB9` 全接受，回帧即 `AUTO+`，与 AUTO 可区分。
- **在线电阻 `0x72`** 可切（与 10-26 日志里 92 帧 `0x72` 对得上）。

**9 处"档位名 ≠ 回帧量程名"（不是 bug）**：

| 档位 | 回帧 Range | 换算 |
|---|---|---|
| 1000V（`0x20/0x60/0xA0`） | 6000V | 60000 counts × 0.1V |
| 6mA（`0x09/0x49/0x89`） | 6000uA | 等值，单位不同 |
| 10A（`0x29/0x69/0xA9`） | 60A | 60000 counts × 1mA |

一个是**档位名**（面板上的档），一个是**满量程名**（比例槽位算出来）。UI 下拉用档位名、读数按满量程比例算，两者不矛盾。
⚠️ 判断项：比例本身还没用已知源验过，建议接 5V 基准切到 1000V 档，读数应约 `5.0 V`。

## 三、温度 ℉ 副显槽位（2026-11-25 实测）

切到 `temp-auto` 后读 5 秒（55 帧），帧内容：

```
主读数   : OL  °C        ← 未接热电偶
副显 1   : OL  °F        ← 华氏，与主读数同步
副显 2   : 20.6 °C INT   ← 内部冷端温度（切档瞬间曾读到 180.8，数秒后收敛到 20.6）
```

**结论**：℉ **不是可下发的 flag**，而是温度帧自带的副显槽位（对应 `ModeSlotMap["TEMP"] = TC/TF/TI`）。
所以上位机做不了"主显示切 ℉"——只能在界面上显示设备给的 ℉ 副显；要主显 ℉ 得在表上操作。

附带发现：内部温度字段切档后需要几秒收敛（180.8 → 20.6），统计面板若把它算进采样会失真——目前主读数用它，不影响；记录时需注意前几帧。

## 五、坑（本次新增）

1. **CLI send 一直"假成功"**：`SendCommand` 是收帧驱动的（`TryPump` 要等下一帧才写出 fff3），原实现发完立刻 `Disconnect` → 命令没写出去却返回 0。判据必须落在回帧的 `data[5]/data[6]` 上。
2. **WinExe + 重定向 = 0 字节**：`AttachConsole` 失败后 `AllocConsole()` 会把输出送到看不见的新控制台。先判 `GetFileType(GetStdHandle(STD_OUTPUT_HANDLE))` 是否 DISK/PIPE。
3. **ModeCatalog 键名拼写**：`Slug("ADC+AC")` = `adc-plusac`（不是 `adc-plus-ac`）。XAML 里写错会静默无反应，已补单测 + `StatusLine` 提示。
4. **测试替身别乱改帧**：FakeMeterSource 若对所有注入帧重算 CRC，会把"CRC 损坏帧"测试用例治好。
5. **`--mac` 也要扫 10 秒**：原 `ConnectAndMeasure` 无条件扫描，自动化每次白等 10s。
